# Frida 速查表（Frida 17.5.2 / Android 15 实测）

> 本表所有 API 均在 Pixel 6 + Android 15 + frida-server 17.5.2 上验证可用。
> 遇到「照着老教程写、结果报错」的情况，先查第一节。

---

## 一、Frida 17 破坏性变更对照（必看）

Frida 17.0 删掉了一批沿用多年的静态方法，旧脚本会直接报 `TypeError: not a function`。

| 旧写法（16.x 及以前） | 新写法（17.x） |
|---|---|
| `Module.getBaseAddress('libx.so')` | `Process.getModuleByName('libx.so').base` |
| `Module.findBaseAddress('libx.so')` | `Process.findModuleByName('libx.so')?.base` |
| `Module.findExportByName('libx.so', 'fn')` | `Process.getModuleByName('libx.so').findExportByName('fn')` |
| `Module.getExportByName('libx.so', 'fn')` | `Process.getModuleByName('libx.so').getExportByName('fn')` |
| `Module.findExportByName(null, 'fn')` | `Module.findGlobalExportByName('fn')` |
| `Module.getExportByName(null, 'fn')` | `Module.getGlobalExportByName('fn')` |
| `Module.findSymbolByName(...)` | `模块对象.findSymbolByName(...)` |
| `Module.enumerateExports('libx.so')` | `Process.getModuleByName('libx.so').enumerateExports()` |
| `Memory.readU32(p)` | `p.readU32()` |
| `Memory.writeU32(p, v)` | `p.writeU32(v)` |
| `Process.enumerateModules({onMatch, onComplete})` | `for (const m of Process.enumerateModules())` |
| `Process.enumerateThreads({onMatch})` | `for (const t of Process.enumerateThreads())` |

**还有一条更隐蔽的**：从 17.0 起，Java bridge 不再内置在 GumJS 中。

- 用 `frida` CLI 加载 → 自带 bridge，`Java.use` 正常
- 用 Python `session.create_script()` 加载 → **`Java is not defined`**

解决：用本目录的 `run_template.py`（自动拼 bridge），或改用 CLI。

## 二、Java 层速查

### 2.1 最小 hook 骨架

```javascript
Java.perform(function () {
  const Cls = Java.use('com.example.Target');
  const m = Cls.methodName.overload('java.lang.String', 'int');
  m.implementation = function (str, num) {
    console.log('入参', str, num);
    const ret = m.call(this, str, num);   // 调原方法
    return ret;                            // 必须 return
  };
});
```

### 2.2 重载怎么选

```javascript
Cls.method.overloads                  // 所有重载数组
Cls.method.overload('int')            // 精确匹配
Cls.method.overload('java.lang.String', '[B')  // 字符串 + byte[]
Cls.method.overloads.forEach(ov => {
  ov.implementation = function () { return ov.call(this, ...arguments); };
});                                    // 全部重载一起 hook
```

> 类型名写法：`int` / `boolean` / `long` / `java.lang.String` / `byte`（基本类型数组是 `[B`）

### 2.3 常用操作

| 目的 | 写法 |
|---|---|
| hook 构造方法 | `Cls.$init.overload('int').implementation = function(i){...}` |
| 读实例字段 | `this.fieldName.value` |
| 写实例字段 | `this.fieldName.value = 新值` |
| 读静态字段 | `Cls.fieldName.value` |
| 找存活实例 | `Java.choose('类名', {onMatch(i){}, onComplete(){}})` |
| 调原方法 | `m.call(this, ...arguments)` |
| 打印栈 | `Log.getStackTraceString(Throwable.$new())` |
| 类型转换 | `Java.cast(obj, Java.use('目标类'))` |
| 造数组 | `Java.array('byte', [1,2,3])` |
| 主动 new | `Cls.$new(参数)` |
| 枚举已加载类 | `Java.enumerateLoadedClasses({onMatch(n){}, onComplete(){}})` |
| 批量找方法 | `Java.enumerateMethods('*crypto*!/encrypt|decrypt/')` |
| 换 ClassLoader | `Java.classFactory.loader = loader` |
| RPC | `rpc.exports = { ping: () => ({ok:true}) }` |

### 2.4 byte[] 打印成 hex

```javascript
function hexOf(javaBytes) {
  const a = Java.array('byte', javaBytes);
  let s = '';
  for (let i = 0; i < a.length; i++) s += ('0' + (a[i] & 0xff).toString(16)).slice(-2);
  return s;
}
```

## 三、Native 层速查

### 3.1 定位函数

```javascript
// 有导出符号
const fn = Process.getModuleByName('libnative-lib.so').getExportByName('Java_com_x_Y');

// 无导出符号：基址 + 偏移（偏移来自 IDA/Ghidra）
const base = Process.getModuleByName('libnative-lib.so').base;
const fn = base.add(ptr('0x8f40'));

// 全局符号（不知道在哪个模块）
const fn = Module.findGlobalExportByName('open');
```

### 3.2 Interceptor 骨架

```javascript
Interceptor.attach(fn, {
  onEnter(args) {
    this.p0 = args[0];                       // 保存给 onLeave 用
    console.log('x0 =', args[0].toInt32());
    // args[1].readCString()                 读 C 字符串
    // args[1].readU32()                     读 4 字节
  },
  onLeave(retval) {
    console.log('返回值', retval);
    retval.replace(ptr(1));                  // 改返回值
  }
});
```

### 3.3 常用片段

| 目的 | 写法 |
|---|---|
| 模块基址 | `Process.getModuleByName('libx.so').base` |
| 模块大小 | `Process.getModuleByName('libx.so').size` |
| 实例导出表 | `模块.enumerateExports()` |
| 实例导入表 | `模块.enumerateImports()` |
| 实例符号表 | `模块.enumerateSymbols()`（含调试符号，更全） |
| 读 C 字符串 | `p.readCString()` |
| 读 UTF-16 | `p.readUtf16String()` |
| 读字节数组 | `p.readByteArray(len)` |
| 写字节 | `p.writeByteArray([1,2,3])` |
| 分配内存 | `Memory.alloc(64)` / `Memory.allocUtf8String('x')` |
| 特征码搜索 | `Memory.scanSync(base, size, 'ff 03 ?? aa')` |
| 调用函数 | `new NativeFunction(addr, 'int', ['pointer'])(arg)` |
| 调用栈 | `Thread.backtrace(ctx, Backtracer.FUZZY)` |
| 符号化地址 | `DebugSymbol.fromAddress(addr)` |
| 指令流 | `Stalker.follow(tid, {events:{call:true}})` |
| 内联 C | `new CModule('int f(){return 1;}')` |
| 改内存保护 | `Memory.protect(page, size, 'rwx')` |
| 寄存器 | `ctx.x0` / `ctx.pc` / `ctx.sp` / `ctx.lr` |
| 当前线程 | `Process.getCurrentThreadId()` |
| 指针判空 | `p.isNull()` |

### 3.4 arm64 常用指令编码（patch 用）

| 指令 | 编码 |
|---|---|
| `nop` | `0xd503201f` |
| `ret` | `0xd65f03c0` |
| `mov w0, #0` | `0x52800000` |
| `mov w0, #1` | `0x52800020` |
| `mov x0, #0` | `0xd2800000` |

> 每条 arm64 指令固定 4 字节，必须 4 字节对齐。

## 四、命令行速查

```bash
# 端口转发（连之前必须做一次）
adb forward tcp:39527 tcp:39527

# 看进程 / 应用
frida-ps -H 127.0.0.1:39527
frida-ps -H 127.0.0.1:39527 -a

# 附加已运行进程
frida -H 127.0.0.1:39527 -n com.example.app -l script.js

# 启动新进程并注入（能抓启动早期）
frida -H 127.0.0.1:39527 -f com.example.app -l script.js --no-pause

# 不用写脚本直接追踪
frida-trace -H 127.0.0.1:39527 -n com.example.app -j '*!*/isRoot/'
frida-trace -H 127.0.0.1:39527 -n com.example.app -i "open*"

# REPL 内
%resume        # 放行被暂停的进程
%reload        # 重载脚本
Java.available # 检查 Java bridge
```

## 五、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `Java is not defined` | frida 17 不再内置 bridge，且用 Python 加载 | 用 `run_template.py` 或 frida CLI |
| `Module.getBaseAddress is not a function` | 17.x 删了静态方法 | 改 `Process.getModuleByName(x).base` |
| `TypeError: not a function` on `Memory.readU32` | 17.x 删了 Memory 静态读写 | 改 `p.readU32()` |
| `ClassNotFoundException`，但类确实存在 | 类在别的 ClassLoader 里 | 遍历 `Java.enumerateClassLoadersSync()` + `Java.classFactory.loader` |
| hook 后 App 无响应 / 崩溃 | `implementation` 里忘了 `return` 原方法结果 | 补 `return m.call(this, ...arguments)` |
| 钩 systemui / system_server 后整机重启 | 系统进程被 hook 后崩溃，牵连 zygote | **不要 hook 系统进程**，换成普通 App 验证 |
| `expected a pointer` | 传了 JS number 而不是 NativePointer | 用 `ptr(0x1234)` 包装 |
| `access violation` | 读空指针或越界 | 先 `isNull()` 判断，长度做 `Math.min` 截断 |
| 脚本加载超时 | 脚本太大或首次初始化 ART 慢 | 增加等待时间；拆分脚本 |
| `frida.ServerNotRunningError` | PC 客户端版本与设备 server 不一致 | 版本对齐，例如都用 17.5.2 |
