========================================
 frida 持久化模块 — 配置说明 (v1.5)
========================================

【这是什么】
开机自动启动 frida-server（sijan2 补丁版 17.5.2，Android 14/15/16 兼容）。
监听 127.0.0.1:<PORT>，PC 端通过 adb forward 连接。
开机自动拉起，日常无需手动运行任何命令。
当前配置会同步显示在「模块列表 -> 说明」里，不需要每次去翻 config.sh。

------------------------------------------------------------------
【一、图形化修改（推荐，v1.5 新增）】
------------------------------------------------------------------
在管理器（SukiSU / KernelSU）模块列表 -> 本模块卡片上点「打开」（WebUI），
可以直接看到并修改：

    当前进程名 / 端口 / 运行状态 / 开机自启状态 / 模块版本
    端口输入框 + 进程名输入框 → 应用并重启（立即生效）
    随机端口 / 随机进程名 快捷按钮
    开机自启开关（关掉后重启手机不会自动运行，模块仍保留）
    PC 端连接命令（一键复制）

改完立刻生效，模块列表说明也会同步刷新。

------------------------------------------------------------------
【二、命令行改端口 / 进程名】(对抗 frida 检测)
------------------------------------------------------------------
    # 查看当前配置 + 用法 + 运行中的实例
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh'

    # 修改端口和进程名（立即生效）
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh 39527 sysmon'

    # 只看运行状态（key=value 格式，供脚本解析）
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh status'

也可以直接编辑 config.sh：

    PORT=39527
    BIN_NAME=sysmon

改完重启手机，或执行：
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh restart'

进程名规则：
  - 即磁盘文件名，Linux 进程名上限 15 字符
  - 只允许字母数字和 . _ -
  - 母本 frida-server 保留；改名副本用硬链接生成
    （与母本同一份数据，不额外占用 52MB，启动也更快）
  - 换进程名时旧副本会自动删除，不会越积越多

端口规则：
  - 1024 - 65535
  - 端口被别的进程占用时会直接报错并显示占用者，不会盲改

------------------------------------------------------------------
【三、开机自启开关】
------------------------------------------------------------------
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh off'
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh on'

off = 创建 noautostart 文件：重启后不自动启动，但模块仍然启用。
（不要用 disable 文件，那是管理器的「模块已禁用」标记，会让整个模块停用。）

------------------------------------------------------------------
【四、改「模块列表」里显示的名字 / 版本】
------------------------------------------------------------------
模块列表显示的内容来自 module.prop。不要手改 module.prop，
用下面的命令改 config.sh，再自动重新生成 module.prop：

    # 改显示名（可含空格，用引号包住）
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh name "System Monitor"'

    # 改显示版本（第一个是版本字符串，第二个是纯数字版本代码，可省略）
    su -c 'sh /data/adb/modules/frida_patched_server/set_config.sh version "1.6.0" 10600'

改完在管理器里「下拉刷新」或退出重进，即可看到新的名字和版本。

说明：
  - 这里的「版本」只是模块列表展示用，可以随便写；
    它和 frida-server 二进制里的版本号（frida --version）无关。
  - 想彻底伪装，把 name 改成普通系统服务的名字即可。
  - module.prop 的 id=frida_patched_server 必须保持不变，
    否则管理器会把它当成另一个模块。

------------------------------------------------------------------
【五、模块列表下面的「说明」是怎么来的】
------------------------------------------------------------------
说明行由 sync_prop.sh 生成，内容形如：

    进程: sysmon | 端口: 127.0.0.1:39527 | PC: adb forward tcp:39527 tcp:39527 | 修改: 打开本模块 WebUI

自动同步时机：
  1) 每次执行 set_config.sh 改端口/进程名/名字/版本后
  2) 每次开机（service.sh 启动时）
  3) 手动：su -c 'sh /data/adb/modules/frida_patched_server/sync_prop.sh'

如果列表里还是旧信息：下拉刷新，或退出管理器再进。

------------------------------------------------------------------
【六、模块列表里的「执行」按钮】
------------------------------------------------------------------
本模块带 action.sh，模块列表里会显示「执行」按钮（部分管理器叫「操作」）。
点一下会弹出：进程名、pid、已运行时长、端口监听状态、开机自启状态、
PC 连接命令、最近日志。
只读，不会重启或修改任何东西。

------------------------------------------------------------------
【七、改了端口后 PC 端怎么连】
------------------------------------------------------------------
    adb forward tcp:<新端口> tcp:<新端口>
    frida -H 127.0.0.1:<新端口> -n <包名> -l <脚本.js>

例（当前配置 39527 / sysmon）：
    adb forward tcp:39527 tcp:39527
    frida -H 127.0.0.1:39527 -n com.dlxx.mam.Internal -l 02_thread_bypass.js

------------------------------------------------------------------
【八、禁用 / 卸载】
------------------------------------------------------------------
    停止自启: set_config.sh off（或 WebUI 里关掉开关）
    彻底卸载: KernelSU / SukiSU 管理器里移除模块

------------------------------------------------------------------
【九、文件说明】
------------------------------------------------------------------
    config.sh         个人配置（端口/进程名/显示名/显示版本；升级不覆盖）
    config.default.sh 出厂默认配置（升级会覆盖，勿存个人配置）
    module.prop       模块列表显示信息（由 sync_prop.sh 生成）
    service.sh        开机自启逻辑
    set_config.sh     配置助手（命令行）
    sync_prop.sh      同步 module.prop 的说明行
    action.sh         「执行」按钮的内容
    webroot/index.html 模块页 WebUI（图形化配置入口）
    frida-server      母本二进制（保留）
    <BIN_NAME>        改名副本（硬链接，自动生成）
